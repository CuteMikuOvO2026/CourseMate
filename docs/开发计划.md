# CourseMate · 课程资料学习助手 · 开发计划

> 依据：`14-课程资料学习助手-项目文档.md`
> 版本：MVP v1（单学生、个人账户、本地部署）
> 周期：6 周

## 1. 项目目标

把散落在课程群、网盘和笔记软件中的课程资料，收敛成一个**可追溯、可练习、可复习**的个人知识库：

- 用自然语言查询已上传的课程材料；
- 每个关键结论都能定位到文件名、页码/幻灯片、章节和原文片段；
- 资料不足时明确拒答，不补全常识；
- 从指定资料生成小测和复习卡，并记录错题与掌握度；
- 从作业说明中提取候选截止日期，经用户确认后形成待办。

一句话验收：**学生能在 3 分钟内完成“上传资料 → 提问 → 打开引用原文”，并愿意在下一门课继续使用。**

## 2. 范围

### 2.1 MVP 必做

1. 账户与课程：注册/登录；创建课程；课程间数据完全隔离。
2. 资料上传与解析：PDF、PPTX、DOCX、Markdown、TXT；显示解析状态与失败原因。
3. 资料库问答：限定单门课程；返回答案、置信状态、引用和原文定位。
4. 引用查看：文件名、页码/幻灯片、章节、原文片段；可打开原文件。
5. 小测：按选定资料生成选择题/简答题；提交后记录对错与解析出处。
6. 复习卡：按选定资料/章节生成问答卡；支持“掌握/不熟”标记。
7. 资料待办：从作业通知提取候选截止日期，用户确认后才保存。

### 2.2 明确不做

| 不做 | 原因 |
|---|---|
| 自动代写作业、论文或代码 | 学习辅助边界与诚信要求 |
| 多人共享资料库与协作 | 先验证个人场景 |
| 把模型回答当作事实 | 以引用和“无依据则拒答”为约束 |
| 第三方日历/微信自动写入 | 避免授权和误操作 |
| 全量 OCR 与手写识别 | 首版只支持可提取文本，扫描件明确报错 |

## 4. 架构与技术选型

```text
React SPA（web/dist，静态托管）
        │ /api/v1，同源 httpOnly Cookie
        ▼
FastAPI（routers → services → SQLAlchemy / SQLite）
        ├─ 私有文件存储 data/files/...
        ├─ BackgroundTasks 解析任务 queued → processing → ready/failed
        ├─ 解析：PyMuPDF / python-pptx / python-docx / MD / TXT
        ├─ 分块：标题 + 页感知，400–700 字，跨页不合并
        ├─ 检索：中文 bigram 分词 + BM25 + 哈希 TF-IDF + RRF
        ├─ 生成：Provider 抽象（offline 默认 / OpenAI 兼容可选）
        └─ 评测：backend/eval/run_eval.py
```

| 层 | 选择 | 说明 |
|---|---|---|
| 运行时 | Python 3.12+（本机 3.14.7 venv） | PyMuPDF `cp310-abi3` wheel 兼容 3.14 |
| 后端 | FastAPI + Uvicorn | 类型校验、自动 OpenAPI |
| 数据 | SQLAlchemy 2 + SQLite（WAL、外键） | `DATABASE_URL` 可切 PostgreSQL；迁移后再引入 Alembic |
| 鉴权 | httpOnly Cookie + JWT（HS256） | SameSite=Lax；密码 PBKDF2-SHA256 + 随机盐 |
| 前端 | React 19 + react-router-dom 7 + Vite 7 | 不使用 `@vitejs/plugin-react`，改用 esbuild automatic JSX |
| 检索 | BM25 + 哈希 TF-IDF + RRF | 无外部模型文件，离线确定性；接口可替换真实 embedding |
| 生成 | offline / OpenAI 兼容 | 无 Key 也能完整验收；`mode` 字段对外标注 |
| 任务 | FastAPI BackgroundTasks | 启动时对账未完成任务；后续可换 Celery |

## 5. 数据模型

| 表 | 关键字段 | 说明 |
|---|---|---|
| `users` | id、username、password_hash、created_at | username 唯一 |
| `courses` | id、user_id、name、semester、color、index_version | 索引缓存版本 |
| `source_files` | id、course_id、name、mime_type、storage_key、status、error_message、warning、page_count、chunk_count | status ∈ queued/processing/ready/failed |
| `document_pages` | id、file_id、page_no、heading、text | PDF 页 / PPT 幻灯片；DOCX/MD/TXT 可空 |
| `chunks` | id、course_id、file_id、ord、page_from、page_to、heading、text | 检索单元 |
| `conversations` / `messages` | course_id；role、content、citations、confidence、abstained | 历史仅展示，不作事实依据 |
| `quizzes` / `quiz_questions` / `quiz_attempts` | 范围、题型、选项、答案、解析、来源 chunk；作答与得分 | 题目可回溯 |
| `flashcards` / `flashcard_reviews` | front、back、source_chunk_ids、mastery；复习记录 | mastery ∈ new/mastered/unfamiliar |
| `tasks` | title、due_at、source_file_id、source_snippet、confirmed、done | 确认后才入库 |

**关键约束**：所有业务查询强制 `course.user_id == current_user.id`；任何接口不得仅凭 ID 返回其他用户的资料。

| 分组 | 接口 |

| 课程 | `GET/POST /api/v1/courses`、`GET/PATCH/DELETE /api/v1/courses/{id}` |
| 资料 | `POST /api/v1/courses/{id}/files`、`GET /api/v1/courses/{id}/files`、`GET /api/v1/files/{id}`、`GET /api/v1/files/{id}/download`、`GET /api/v1/files/{id}/pages/{page_no}`、`POST /api/v1/files/{id}/reprocess`、`DELETE /api/v1/files/{id}` |
| 问答 | `POST /api/v1/courses/{id}/query`、`GET /api/v1/courses/{id}/conversations`、`GET /api/v1/conversations/{id}/messages` |
| 小测 | `POST /api/v1/courses/{id}/quizzes`、`GET /api/v1/quizzes/{id}`、`POST /api/v1/quizzes/{id}/attempts`、`GET /api/v1/courses/{id}/attempts` |
| 复习卡 | `GET/POST /api/v1/courses/{id}/flashcards`、`POST /api/v1/courses/{id}/flashcards/generate`、`POST /api/v1/flashcards/{id}/reviews` |

## 7. 关键实现方案

### 7.1 摄入

1. 校验扩展名、魔数、大小（≤50 MB）与课程归属；
2. 按格式提取带页码/幻灯片编号的文本；
3. 标题 + 页感知分块，目标 400–700 字、重叠约 80 字、单块 ≤1200 字，跨页不合并；
4. 写入 `document_pages` 与 `chunks`，课程 `index_version+1`；
5. 状态 `queued → processing → ready / failed`，失败原因面向用户可读。

### 7.2 检索与回答

1. 查询强制 `user_id + course_id` 过滤；
2. 中文 bigram + 英文/数字分词（去停用词）；
3. BM25 与哈希向量各取 Top-50，RRF（k=60）融合，取 Top-6；
4. 低分/低覆盖/空结果直接拒答；
5. 离线模式：按查询词覆盖度和 chunk 排名选句，组成带 `[n]` 的要点；
6. 在线模式：把编号段落送入模型，要求 JSON `{answer, citation_indices, confidence, abstained}`，服务端二次校验引用编号；
7. 任何关键结论必须带有效引用，否则拒答或降级。

### 7.3 小测

- 从候选句挖空高频术语生成单选题，干扰项取同课程其他 chunk 的术语；
- 简答题按“术语 + 关键词覆盖”自动判分，并允许用户改判；
- 每题保存 `source_chunk_ids`、解析与引用；
- 作答记录写入 attempts，错题可回查。

### 7.4 复习卡与待办

- 复习卡由“术语 + 解释句”或挖空生成，支持手建；复习写入 review 表并更新 mastery；
- 待办用正则提取“截止/提交/deadline”、绝对/相对日期与时间，生成**候选**，用户确认后才创建任务；相对日期或缺年份标记为待确认。

### 7.5 鉴权与存储

- 注册：用户名唯一、密码 ≥8 位、PBKDF2-SHA256（31 万次）+ 16 字节盐；
- 会话：HS256 JWT 写入 httpOnly Cookie，7 天过期，SameSite=Lax；
- 文件：`data/files/{course_id}/{file_id}{ext}`，生成式文件名，下载与删除均校验归属；
- 删除课程：级联删除文件、页、chunk、会话、小测、卡片、待办与磁盘文件。

## 9. 六周排期与任务拆解

### 第 1 周：骨架、账户、课程、上传

- 任务：仓库骨架与脚本；用户/课程模型与鉴权；课程 CRUD；上传校验与私有存储；文件列表/下载/删除；前端登录、课程列表、上传与文件列表。
- 产出：能创建课程并上传/查看文件。
- 验收：鉴权与越权测试通过；上传非法类型/超大文件有明确错误。

### 第 2 周：解析、分块、索引

- 任务：5 类解析器（页码/幻灯片/标题）；扫描件识别；状态流转与启动对账；页文本接口；分块；BM25 + 哈希向量 + RRF；索引缓存与失效。
- 产出：文件显示解析状态，可检索原文。
- 验收：5 种格式解析成功；失败原因可读；Recall@5 初测可运行。

### 第 3 周：带引用问答与拒答（已完成）

- 已完成：检索管线；离线原文摘录与拒答；会话/消息持久化；服务端引用校验；可选 OpenAI 兼容 provider；前端问答与出处查看。
- 产出：回答可定位到文件、页码/幻灯片或章节，无依据时拒答。
- 待第 6 周用评测集验证：引用定位合法率 100%；无答案问题拒答率 ≥80%；p95 ≤8 秒。

### 第 4 周：小测、作答与错题（已完成）

- 已完成：选择题/简答题生成；资料范围校验；关键词覆盖判分与简答题人工改判；作答记录与错题回看；前端练习流程。
- 产出：从指定资料生成并完成练习，查看成绩和逐题出处。
- 待完整回归验证：题目均有来源与解析；错题可复现；跨用户访问隔离。

### 第 5 周：复习卡、待办、前端打磨（已完成）

- 已完成：复习卡生成/手建/翻面复习与掌握度记录；截止日期候选提取、用户确认后入库、逾期/完成/编辑/删除；课程级联删除；前端「复习卡」「待办」页与移动端布局。
- 产出：形成「问答 → 小测 → 复习卡 → 待办」的个人复习闭环。
- 验收：全量 64 个 pytest 用例通过；前端构建通过；课程删除级联测试覆盖复习卡、复习记录与待办。

### 第 6 周：评测、试用、部署与文档

- 任务：种子课程与 40 条评测集；评测脚本与报告；README、架构文档；启动验证。

- 验收：第 11 节指标达标；`http://127.0.0.1:8000` 可演示。

## 10. 测试与评测

- **单元**：分词、分块、BM25/向量/RRF、拒答阈值、引用校验、日期提取、密码哈希、JWT。
- **集成**：注册登录、课程 CRUD、5 格式上传→解析→ready、问答、小测、卡片、待办、下载鉴权、级联删除。
- **越权**：用户 B 访问用户 A 的课程/文件/对话/题目/卡片一律 404；跨课程检索不串数据。
- **评测集**：40 条（32 条可答 + 8 条无答案，≥15%），覆盖 5 类资料。
- **指标**：Recall@5、引用定位合法率、抽样支持率、拒答率、p95、解析成功率。
- **支持率**：抽取 20 条回答人工标注，报告附表格。

## 11. 验收标准

| 维度 | 指标 | 目标 |
|---|---|---|
| 检索 | Recall@5 | ≥ 0.80 |
| 引用 | 页码/文件定位合法率 | 100% |
| 引用 | 抽样支持率 | ≥ 90% |
| 拒答 | 无答案问题正确拒答率 | ≥ 80% |
| 体验 | 已索引课程问答 p95 | ≤ 8 秒 |
| 可靠性 | 上传后解析成功率（支持类型） | ≥ 95% |

另：3–5 位同学的任务测试（上传资料、找到作业要求、完成一次小测）安排在发布后执行。

## 12. 风险与应对

| 风险 | 应对 |
|---|---|
| 无 API Key 时回答为摘录式 | 默认离线 provider；界面标注 `mode`；README 给 OpenAI 兼容配置 |
| 中文检索效果 | bigram 分词 + 双路检索 + RRF；评测集校准拒答阈值 |
| 扫描 PDF 无文本 | 明确 failed + 原因，不伪造成功；OCR 列为后续 |
| PPT 排版复杂 | 以幻灯片为最小定位单位；保留原文件 |
| 生成题目错误 | 每题显示来源；用户可标记“题目有误”（后续） |
| 数据串库 | 强制 user_id/course_id；专项越权测试 |
| 文件与学习记录隐私 | 私有存储、下载鉴权、删除级联 |
| 后台任务中断 | 启动时重新入队 queued/processing |

## 13. 运行与部署

```powershell
# 1. 安装后端依赖（本机使用 scripts/setup.ps1）
pwsh -File scripts/setup.ps1

# 2. 构建前端（需要 Node/pnpm；沙箱环境下需完全访问权限）
pwsh -File scripts/build-web.ps1

# 3. 种子演示数据
cd backend
..\.venv\Scripts\python.exe scripts\seed_demo.py

# 4. 启动
pwsh -File scripts/run.ps1   # http://127.0.0.1:8000

# 5. 测试与评测
cd backend
..\.venv\Scripts\python.exe -m pytest -q
..\.venv\Scripts\python.exe eval\run_eval.py
```

环境变量见 `.env.example`：`COURSEMATE_DATA_DIR`、`COURSEMATE_DATABASE_URL`、`COURSEMATE_SECRET_KEY`、`COURSEMATE_MAX_UPLOAD_MB`、`COURSEMATE_LLM_PROVIDER` 等。
